# Clothing Hygiene — 기획서

림월드 1.6 (Unity Mono, net472) · 모드 packageId `hong.clothinghygiene`

---

## 1. 한 줄 정의

**입고 있는 옷이 시간에 따라 더러워지고, 더러우면 기분이 나빠지며, 갈아입거나 빨아야 해결되는** 의복 위생 시스템.

바닐라의 두 페널티(**유품옷 Tainted** = 죽은 사람이 입던 옷, **내구도 50% 이하**)와 **완전히 독립**이다.
멀쩡하고 새 옷이어도 며칠 입으면 갈아입어야 한다.

## 2. 왜 만드는가

- Dubs Bad Hygiene 는 **신체 위생**(목욕·배설·배관)이지 **의복 오염**이 아니다.
- 기존 세탁 모드(Easy Laundry, Holy Washer, Wash Clothes 등)는 **이미 더러워진 옷을 씻는** 도구다.
  "왜 더러워졌는가"라는 원인 시스템이 없다.
- 이 모드는 **원인(착용 경과)** 을 만들고, 그 결과로 세탁·갈아입기가 **필요해지게** 한다.

## 3. 코어 루프

```
착용 → 오염 누적 → 단계 상승 → 무드 페널티
                 ↓
        (a) 예비 복으로 갈아입기   (b) 세탁해서 다시 입기
                 ↓                        ↓
            깨끗한 옷 확보 ←────── 재고·생산 ──────┘
```

핵심은 **자동 갈아입기**다. 오염도만 만들고 끝내면 "무드 디버프 하나 추가한 모드"가 된다.
깨끗한 예비 옷을 확보하고, 폰이 스스로 갈아입는 행동까지 있어야 플레이가 성립한다.

## 4. 시스템 명세

### 4.1 오염도 (HygieneValue)

| 항목 | 값 |
|---|---|
| 저장 단위 | **의복 1벌당** `float 0.0 ~ 1.0` |
| 저장 위치 | 의복 ThingComp (`ch_filth`), 세이브에 포함 |
| 독립성 | `hitPoints`·`Tainted` 를 **읽지도 쓰지도 않는다** |
| 표시 | 의복 inspect 문자열 (`청결도: 찝찝함 (74%)`) |

### 4.2 누적 규칙

기본: **하루 60,000틱에 80%** → 70% 임계까지 약 21시간. "거의 매일 갈아입어야" 요구를 만족하는 초기값.

누적량 = `(80% / 60,000) × 경과틱 × 활동계수 × 의복계수`

| 활동 상태 | 계수 | 근거 |
|---|---|---|
| 수면 | ×0.4 | 땀 적음 |
| 평상시·실내 | ×1.0 | 기준 |
| 노동(제작·건설·농사·운반) | ×1.5 | 땀 |
| 격렬(광산·화재진압·전투) | ×2.5 | 이 모드의 존재 이유 |
| 더위(기온 30℃ 이상) | ×1.3 추가 | 환경 |
| 추위(0℃ 이하) | ×0.7 | 겹겹이 입어 덜 더러움 |

의복계수: 속옷·얇은 옷 ×0.7, 일반 ×1.0, 방한복·판금 ×1.4 (comp props `filthFactor`).

### 4.3 단계와 무드

| 오염도 | 단계 | 무드 | 비고 |
|---|---|---|---|
| 0~20% | 깨끗함 | +1 | 하루 시작 보너스 |
| 20~50% | 사용감 | 0 | 무해 |
| 50~70% | 냄새남 | −3 | 첫 경고 |
| 70~90% | 찝찝함 | −6 | **자동 갈아입기 임계** |
| 90~100% | 매우 더러움 | −10 | 사회적 페널티(추후) |

- 무드는 **가장 더러운 한 벌** 기준(합산 금지 — 옷 5벌이면 −50 이 되는 걸 막는다).
- ThoughtDef 는 단계별 4개. `Nullifying` 조건: 그 옷을 벗으면 즉시 사라짐.

### 4.4 세탁

- **세탁통(basin)**: 수동, 소량. 연구 불필요(초반부터 쓸 수 있게).
- **세탁기(washing machine)**: 전력 소비, 자동 반복. `Electricity` 연구.
- 비용: 물(모드 자체 자원) + 세제(선택). Dubs Bad Hygiene 설치 시 파이프 물을 쓰도록 선택 연동.
- 결과: 오염도 0. **내구도는 약간 소모**(세탁은 옷을 닳게 한다) — 기본 −2%p, 설정으로 0 가능.
- Tainted 는 **제거하지 않는다** (그건 별개 축, Holy Washer 계열 모드의 역할).

### 4.5 자동 갈아입기

조건(모두 참):
1. 착용 중인 어떤 옷이든 오염 ≥ 70%
2. 같은 슬롯(가슴/다리/머리)의 **깨끗한 예비복**이 접근 가능(재고·바닥·선반)
3. 예비복 조건: 오염 < 20% ∧ 내구도 > 50% ∧ 착용 가능(성별·계급·바이오코드 통과)

행동: `JobDef_ChangeClothing` — 예비복으로 이동 → `Wear(newApparel, dropReplaced: true)` → 벗은 옷은 그 자리에 떨어뜨림(forbid=false).
우선순위는 중간(RimWorld `JobGiver` 계층에서 식사·수면 아래, 유휴 작업 위).

### 4.6 설정 (ModSettings)

| 항목 | 기본 | 범위 |
|---|---|---|
| 하루 오염도 | 80% | 10~200% |
| 자동 갈아입기 임계 | 70% | 30~100% |
| 세탁 시 내구도 손실 | 2%p | 0~10%p |
| 오염 무드 페널티 배율 | 1.0 | 0~2.0 |
| 무드 페널티 끄기 | off | — |

## 7. 성능 예산 (틱 1순위)

| 항목 | 목표 |
|---|---|
| 틱 진입 | `TicksGame % 250` 가드, 1회/250틱 |
| 순회 대상 | `AllPawnsSpawned` (무할당) × 착용 의복 |
| 예상 부하 | 콜로니스트 30명 × 5벌 = 150 comp / 250틱 → 틱당 0.6회 |
| 틱 루프 내 할당 | 0 (LINQ·문자열·클로저 금지) |
| 측정 | Dubs Performance Analyzer + 자체 Stopwatch 누적(일 1회 로그) |

측정 없이 최적화하지 않는다. 최적화 주장은 전후 수치로만 한다.

## 8. 검증 시나리오 (인게임)

1. 새 게임 → 개발자 모드 → 의복 inspect 에 `청결도` 표시
2. 3배속 1일 → 착용 의복 오염도 상승, 80% 근처
3. 70% 도달 → `찝찝함` 무드 확인(무드 탭에서 thought 이름)
4. 세탁통에서 세탁 → 오염 0, 내구도 −2%p
5. 예비복을 재고에 두고 대기 → 폰이 스스로 갈아입고 벗은 옷이 바닥에 떨어짐
6. 세이브 → 로드 → 오염도 유지
7. 모드 제거 후 로드 → 오류 없이 로드(상태만 사라짐)
8. 100명 규모 맵에서 TPS 저하 없음(DPA 비교)
