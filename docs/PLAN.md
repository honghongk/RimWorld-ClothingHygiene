# Clothing Hygiene — 기획서

림월드 1.6 (Unity Mono, net472) · 모드 packageId `hong.clothinghygiene`

---

## 1. 한 줄 정의

**입고 있는 옷이 시간에 따라 더러워지고, 더러우면 기분이 나빠지며, 갈아입거나 빨아야 해결되는** 의복 위생 시스템.

바닐라의 두 페널티(**유품옷 Tainted** = 죽은 사람이 입던 옷, **내구도 50% 이하**)와 **완전히 독립**이다.
멀쩡하고 새 옷이어도 며칠 입으면 갈아입어야 한다.

## 2. 왜 만드는가

- Dubs Bad Hygiene 는 **신체 위생**(목욕·배설·배관)이지 **의복 오염**이 아니다.
- 기존 세탁 모드(Easy Laundry, Holy Washer, Wash Clothes 등)는 **이미 더러워진 옷을 씻는** 도구다.
  "왜 더러워졌는가"라는 원인 시스템이 없다.
- 이 모드는 **원인(착용 경과)** 을 만들고, 그 결과로 세탁·갈아입기가 **필요해지게** 한다.

## 3. 코어 루프

```
착용 → 오염 누적 → 단계 상승 → 무드 페널티
                 ↓
        (a) 예비 복으로 갈아입기   (b) 세탁해서 다시 입기
                 ↓                        ↓
            깨끗한 옷 확보 ←────── 재고·생산 ──────┘
```

핵심은 **자동 갈아입기**다. 오염도만 만들고 끝내면 "무드 디버프 하나 추가한 모드"가 된다.
깨끗한 예비 옷을 확보하고, 폰이 스스로 갈아입는 행동까지 있어야 플레이가 성립한다.

## 4. 시스템 명세

### 4.1 오염도 (HygieneValue)

| 항목 | 값 |
|---|---|
| 저장 단위 | **의복 1벌(개별 Thing)당** `float 0.0 ~ 1.0` — 슬롯·폰·콜로니 단위가 아니다 |
| 저장 위치 | 각 의복의 ThingComp(`ch_filth`), 그 아이템의 세이브 노드에 포함 |
| 독립성 | `hitPoints`·`Tainted` 를 **읽지도 쓰지도 않는다** |
| 표시 | 의복 inspect 문자열 (`청결도: 찝찝함 (74%)`) |

**"한 벌 = 한 값"이 이 모델의 핵심 제약이다.**

- 같은 종류의 옷 2벌은 **완전히 별개 값**을 갖는다. A 를 빨아도 B 는 그대로 더럽다.
- 옷을 벗어 바닥·재고·선반에 두거나 다른 림에게 넘겨도 오염도는 **그 아이템을 따라간다**(컴포넌트는 Thing 에 붙어 있으므로).
- 새로 만든 옷·상점에서 산 옷은 0% 로 시작한다.
- 폰 단위로 캐싱하지 않는다 — 폰이 갈아입으면 다음 틱 순회는 새 옷의 값을 읽는다.
- 재질·종류별 차이는 **값이 아니라 계수**(`filthFactor`)로 표현한다. 벌마다 다른 값만 다르다.

### 4.2 누적 규칙

기본: **하루 60,000틱에 80%** → 70% 임계까지 약 21시간. "거의 매일 갈아입어야" 요구를 만족하는 초기값.

누적량 = `(80% / 60,000) × 경과틱 × 활동계수 × 의복계수`

| 활동 상태 | 계수 | 근거 |
|---|---|---|
| 수면 | ×0.4 | 땀 적음 |
| 평상시·실내 | ×1.0 | 기준 |
| 노동(제작·건설·농사·운반) | ×1.5 | 땀 |
| 격렬(광산·화재진압·전투) | ×2.5 | 이 모드의 존재 이유 |
| 더위(기온 30℃ 이상) | ×1.3 추가 | 환경 |
| 추위(0℃ 이하) | ×0.7 | 겹겹이 입어 덜 더러움 |

의복계수: 속옷·얇은 옷 ×0.7, 일반 ×1.0, 방한복·판금 ×1.4 (comp props `filthFactor`).

### 4.3 단계와 무드

| 오염도 | 단계 | 무드 | 중첩 |
|---|---|---|---|
| 0~20% | 깨끗함 | **+1** | **가능 — 깨끗한 벌마다 +1, 최대 +5** |
| 20~50% | 사용감 | 0 | — |
| 50~70% | 냄새남 | −3 | 불가 |
| 70~90% | 찝찝함 | −6 | 불가 (**자동 갈아입기 임계**) |
| 90~100% | 매우 더러움 | −10 | 불가 |

- **보너스는 중첩**: `min(깨끗한 착용 벌 수, 5)` → 최대 +5. 옷을 잘 관리한 콜로니가 보상받는다.
- **디버프는 중첩 불가**: 착용 의복 중 **가장 더러운 한 벌**의 단계만 적용한다. 옷 5벌이 −50 이 되는 것을 막는다.
- ThoughtDef 는 보너스 1개(`CH_Clean`, stackLimit 5) + 디버프 3개(`CH_Smelly`·`CH_Clammy`·`CH_Filthy`), 디버프는 상호 배타.
- `Nullifying` 조건: 해당 옷을 벗거나 세탁하면 즉시 사라짐.
- 무드는 착용 상태가 바뀔 때만 재계산한다(매 틱 계산 금지 — §7).

### 4.4 세탁 — 연구로 푸는 계단

기본 빨래는 **연구 없이** 가능하다. 편해지는 것은 연구로 연다.

| 시대 | 수단 | 물 | 세제 | 연구 |
|---|---|---|---|---|
| 아무 시대 | **손빨래** — 물가/세탁통, 벌당 수동 작업 | 선택 | 불필요 | 없음 |
| 중세 | **세탁통(basin)** — 전용 작업대, 여러 벌 한 번에 | 필요 | 잿물(선택) | `ClothingHygiene_Basin` |
| 산업 | **비누** — 세제 생산 | — | 생산 | `ClothingHygiene_Soap` |
| 산업 | **세탁기** — 전력, 자동 반복 | 필요 | 필요 | `ClothingHygiene_Washer` + `Electricity` |
| 우주 | **초음파 세탁기** — 물·세제 절반, 작업 속도 2배 | 필요 | 필요 | `ClothingHygiene_UltraSonic` |

- 결과: 오염도 0. **내구도는 약간 소모**(기본 −2%p, 설정으로 0 가능). 세탁은 옷을 닳게 한다.
- 세제가 없으면 오염도 40%까지만 감소(부분 세탁). 연구·생산 없이도 "완전히"는 아니지만 개선된다.
- Tainted 는 **제거하지 않는다** (별개 축, Holy Washer 계열 모드의 역할).

#### 4.4.1 물 — 소프트 의존

| 환경 | 동작 |
|---|---|
| **Dubs Bad Hygiene 활성** | 배관망 물을 소비. 배관이 없으면 물통/우물로 대체 |
| **DBH 미설치** | 물 없이 세탁(자체 물 자원을 새로 만들지 않는다) |

- 하드 의존 금지: `Dubwise.DubsBadHygiene` 를 **컴파일 참조하지 않는다**. 활성 여부만 감지하고, 물 인출은 리플렉션 또는 어댑터로 격리.
- **세탁기는 자체 구현한다**(확정). DBH 물만 빌린다.
- 연구·건물·세제는 DBH 유무와 무관하게 동작해야 한다(무물 모드에서도 게임이 성립).
- DBH 물 인출 API 는 **미확인** — 후보 진입점 `DubsBadHygiene.CompPipe` / `CompWaterFillable`(`Water`·`HasWater`·`Fill()`) / `CompWaterStorage`.

#### 4.4.2 DBH 자체 세탁기와의 관계 (실측)

DBH 에는 이미 세탁기가 있다 — 실측(워크샵 836308268, modVersion 3.2.3260, 1.6 폴더):

| 항목 | 값 |
|---|---|
| ThingDef | `WashingMachine` (`BuildingsC_Joy.xml`), 라벨 "washing machine", 1×1 |
| thingClass | `DubsBadHygiene.Building_WashingMachine` (`innerContainer` + `CompPipe`(Sewage) + `CompPowerTrader` 420W) |
| 연구 | `WashingMachines` — Industrial, baseCost 1200, 선행 `ElectricPumps` |
| 효과 | **Tainted 제거** ("you can't even tell someone died wearing it") |
| 숨김 조건 | def·연구 둘 다 `DBHLite="true"` → DBH **Lite 모드** 켜면 사라짐 (이 설치본은 `LiteMode=False`) |

→ **역할이 다르다.** DBH 세탁기 = Tainted 제거, 이 모드 세탁기 = **오염도(착용 경과) 제거**.
둘 다 존재하는 것이 정상이며, 우리 세탁기는 Tainted 를 건드리지 않는다(§4.4).
호환 패치(선택): DBH 세탁기 사이클이 끝나면 오염도도 0 으로 — M5c 후순위.

### 4.5 자동 갈아입기

조건(모두 참):
1. 착용 중인 어떤 옷이든 오염 ≥ 70%
2. 같은 슬롯(가슴/다리/머리)의 **깨끗한 예비복**이 접근 가능(재고·바닥·선반)
3. 예비복 조건: 오염 < 20% ∧ 내구도 > 50% ∧ 착용 가능(성별·계급·바이오코드 통과)

행동: `JobDef_ChangeClothing` — 예비복으로 이동 → `Wear(newApparel, dropReplaced: true)` → 벗은 옷은 그 자리에 떨어뜨림(forbid=false).
우선순위는 중간(RimWorld `JobGiver` 계층에서 식사·수면 아래, 유휴 작업 위).

### 4.6 설정 (ModSettings)

| 항목 | 기본 | 범위 |
|---|---|---|
| 하루 오염도 | 80% | 10~200% |
| 자동 갈아입기 임계 | 70% | 30~100% |
| 세탁 시 내구도 손실 | 2%p | 0~10%p |
| 오염 무드 페널티 배율 | 1.0 | 0~2.0 |
| 깨끗함 보너스 상한 | +5 | 0~+10 |
| 무드 페널티 끄기 | off | — |
| 세제 요구 | on | on/off |
| 물 사용 | 자동 감지 | 자동 / 강제 무물 / 강제 필요 |

## 7. 성능 예산 (틱 1순위)

| 항목 | 목표 |
|---|---|
| 틱 진입 | `TicksGame % 250` 가드, 1회/250틱 |
| 순회 대상 | `AllPawnsSpawned` (무할당) × 착용 의복 |
| 예상 부하 | 콜로니스트 30명 × 5벌 = 150 comp / 250틱 → 틱당 0.6회 |
| 틱 루프 내 할당 | 0 (LINQ·문자열·클로저 금지) |
| 측정 | Dubs Performance Analyzer + 자체 Stopwatch 누적(일 1회 로그) |

측정 없이 최적화하지 않는다. 최적화 주장은 전후 수치로만 한다.

## 8. 검증 시나리오 (인게임)

1. 새 게임 → 개발자 모드 → 의복 inspect 에 `청결도` 표시
2. 3배속 1일 → 착용 의복 오염도 상승, 80% 근처
3. 70% 도달 → `찝찝함` 무드 확인(무드 탭에서 thought 이름)
4. 세탁통에서 세탁 → 오염 0, 내구도 −2%p
5. 예비복을 재고에 두고 대기 → 폰이 스스로 갈아입고 벗은 옷이 바닥에 떨어짐
6. 세이브 → 로드 → 오염도 유지
7. 모드 제거 후 로드 → 오류 없이 로드(상태만 사라짐)
8. 100명 규모 맵에서 TPS 저하 없음(DPA 비교)

## 9. 리스크 / 미확인

| 항목 | 상태 |
|---|---|

| XML 패치가 실제로 의복 comp 를 붙이는지 | **미확인(인게임 필요)** |

| 자동 갈아입기 JobGiver 삽입 지점 | 미확인 — `Pawn_JobTracker`/`ThinkTree` 조사 필요 |
| DBH 물 인출 API | **미확인** — `CompPipe` 의 물망에서 차감하는 메서드 조사 필요 |
